## 직무별 포트폴리오 신호

### 금융 계정계·백엔드

보여줄 증거:

- 원장 불변식과 복구 가능한 migration
- 경합·중복 요청에서의 자금 보존
- 배치 재시작과 대사 차이 처리
- 잠금 전략을 선택한 기준과 감수한 비용

금지할 과장:

- 작은 개인 장비 실험을 `대규모 계정계`로 표현
- 단순 CRUD를 `코어뱅킹 완성`으로 표현
- 원장 테이블을 만들었다는 이유만으로 회계 도메인을 전부 이해한다고 주장

### 결제·핀테크 백엔드

보여줄 증거:

- 승인·매입·취소·환불의 전체 상태 전이
- 중복 webhook과 파트너 장애 복구
- 거래와 정산의 불일치 탐지
- 모듈 유지와 서비스 분리의 before/after 비용

금지할 과장:

- stub 연동을 실제 PG 연동으로 표현
- outbox를 exactly-once로 표현
- 서비스 하나를 분리한 것을 전사 MSA 경험으로 표현

### 금융 AI 응용

보여줄 증거:

- 규칙 기준선과 모델 결과의 분리 비교
- 합성 데이터의 생성 규칙과 한계
- retrieval, 인용, 수동 사실 확인을 분리한 RAG 평가
- 모델·프롬프트·문서 버전, 비용, 지연, 보안 평가
- Agent와 승인자의 분리된 권한

금지할 과장:

- 합성 FDS 성능을 실제 사기 탐지율로 일반화
- LLM 평가만으로 정확도를 입증
- Agent가 실제 금융 판단을 대신한다고 표현

## 최종 감사 시 시장 재검증

1. 위 공식 공고를 다시 열어 유지·변경 여부를 기록합니다.
2. 지원할 실제 채용공고 3~5개를 추가하고 공통 요구사항을 추출합니다.
3. 대표 사례 네 개만 실제 공고의 업무·자격요건과 연결합니다.
4. 계획에만 있고 구현되지 않은 스택은 제거합니다.
5. 공고가 요구해도 증거가 없는 역량은 `학습 예정`이 아니라 포트폴리오 본문에서 제외합니다.
