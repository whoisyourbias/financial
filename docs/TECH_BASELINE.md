# 기술 기준선과 공통 계약

## 목적

이 문서는 12개 프로젝트가 서로 다른 표현과 임의의 기술 선택으로 흩어지지 않도록 기준선을 고정합니다. 계획에 적힌 기술은 구현 경험을 의미하지 않으며, 실제 사용 여부는 코드와 증거가 생긴 뒤에만 포트폴리오 스택에 반영합니다.

## 버전 기준

| 영역            | 기준                        | 정책                                                      |
| --------------- | --------------------------- | --------------------------------------------------------- |
| JVM             | Eclipse Temurin Java 21 LTS | 전 프로젝트 고정. 버전 변경은 별도 ADR 필요               |
| 애플리케이션    | Spring Boot 4.1.x           | 프로젝트 01 시작 시 호환 patch를 wrapper·lockfile에 고정  |
| AI              | Spring AI 2.x               | 프로젝트 11에서 도입. Boot 호환 조합을 통합 테스트로 고정 |
| 빌드            | Gradle Wrapper              | 로컬 설치 버전에 의존하지 않음                            |
| 주 데이터베이스 | PostgreSQL                  | Flyway migration만으로 스키마 변경                        |
| 테스트          | JUnit 5, Testcontainers     | 데이터베이스·브로커 통합 테스트에 실제 컨테이너 사용      |
| 로컬 실행       | Docker Compose              | 한 명이 명령 하나로 의존성을 재현할 수 있어야 함          |

patch 업데이트는 기능 개발과 분리합니다. 보안·호환성 이유가 아니면 프로젝트 도중 버전을 올리지 않으며, 업데이트 전후 테스트 결과를 기록합니다.

## 애플리케이션 구조

프로젝트 01~08은 단일 배포 단위 안의 모듈러 모놀리스입니다.

```text
platform/
├── bootstrap
├── ledger
├── payment
├── webhook
├── virtual-account
├── settlement
├── identity-audit
├── merchant-sample
└── shared-kernel
```

- 도메인 모듈은 다른 모듈의 영속 엔티티나 repository에 직접 접근하지 않습니다.
- `shared-kernel`에는 `Money`, 식별자, 시간 추상화, 오류 계약처럼 정말 공통인 값만 둡니다.
- 편의를 위한 공용 서비스 모음은 만들지 않습니다.
- 프로젝트 09에서 payment command와 read model 경계를 별도 프로세스로 분리해보고, 비용이 이점보다 크면 원복할 수 있습니다.
- FDS와 AI는 핵심 원장과 다른 실패 경계를 가지며, 장애가 거래 기록을 막지 않도록 비동기 소비자 또는 읽기 전용 인터페이스로 연결합니다.

## 금액 계약

```java
public record Money(long amountMinor, Currency currency) {}
```

- `Currency`는 ISO-4217 코드와 소수 자릿수를 가집니다.
- 저장·전송·계산에 `double`과 `float`를 사용하지 않습니다.
- KRW는 소수 자릿수 0으로 시작하지만 계약 자체는 통화를 고정하지 않습니다.
- 수수료·환율처럼 나눗셈이 필요한 계산은 연산별 반올림 정책을 이름으로 명시합니다.
- 서로 다른 통화의 덧셈·비교는 실패시킵니다.
- 표시용 포맷과 저장용 값은 분리합니다.

## 변경 API 계약

토스페이먼츠 공개 계약이 지원한다고 명시한 POST API는 공개 `Idempotency-Key` 동작을 따릅니다. sandbox 관리 API와 내부 command는 별도 정책으로 같은 키·같은 본문의 한 비즈니스 결과를 강제합니다.

- 키의 유효 범위는 `호출 주체 + 작업 종류 + 키`입니다.
- 같은 키와 같은 요청은 처음 확정된 결과를 반환합니다.
- 같은 키와 다른 요청 본문은 충돌 오류를 반환합니다.
- 처리 중 상태와 확정 상태를 구분합니다.
- 멱등 처리를 `exactly-once`로 부르지 않습니다.

표준 오류 응답은 다음 필드를 가집니다.

```json
{
  "code": "ALREADY_PROCESSED_PAYMENT",
  "message": "요청을 처리할 수 없습니다."
}
```

- `message`에 개인정보·내부 SQL·스택트레이스를 포함하지 않습니다.
- 클라이언트 분기는 `code`를 사용합니다.
- HTTP 상태와 비즈니스 코드를 API 문서에 함께 기록합니다.
- public 호환 API의 Error body에는 문서화하지 않은 필드를 추가하지 않습니다.
- correlation ID와 상세 진단은 응답 헤더·내부 로그에 두고, `/sandbox/**`·`/sandbox/ops/**` 확장 응답은 별도 schema로 표시합니다.

## 이벤트 계약

```json
{
  "eventId": "uuid",
  "eventType": "payment.status.changed",
  "schemaVersion": 1,
  "occurredAt": "2026-09-01T00:00:00Z",
  "correlationId": "uuid",
  "aggregateId": "uuid",
  "payload": {}
}
```

- 전달 보장은 `at-least-once`를 기준으로 하며 소비자가 `eventId`로 중복을 억제합니다.
- 이벤트 스키마는 추가적 변경을 우선하고 파괴적 변경은 새 버전으로 발행합니다.
- outbox 저장과 비즈니스 변경은 같은 데이터베이스 트랜잭션에 포함합니다.
- broker publish와 소비자 처리는 중복·지연·순서 역전을 정상 가능성으로 취급합니다.
- DLQ는 해결책이 아니라 조사와 재처리를 위한 격리 지점입니다.

## AI 응답·도구 계약

AI 응답에는 다음 메타데이터를 보관합니다.

- 모델 provider·model ID·버전
- prompt template 버전
- 검색 문서 ID·버전·인용 위치
- 평가 corpus 버전과 평가 결과
- 요청·응답 지연과 비용 산정 기준
- 개인정보 마스킹과 안전 필터 결과

모델이 산출한 임의의 확률을 신뢰도로 표시하지 않습니다. RAG 품질은 retrieval 지표, 인용 일치, 수동 사실 확인을 분리해 보고합니다.

AI 도구는 다음 등급으로 나눕니다.

1. `READ`: 합성 거래·정책 조회. 즉시 실행 가능
2. `PROPOSE`: 취소·환불 같은 변경 초안 생성. 영속 상태 변경 금지
3. `APPROVE`: 인증된 사람이 초안을 검토하고 별도 API로 승인
4. `EXECUTE`: 승인 ID·버전·만료 시간을 검증한 결정론적 서비스만 수행

Agent는 `APPROVE`와 `EXECUTE` 권한을 가지지 않습니다.

## 데이터와 비밀정보

- 모든 데이터 생성기는 seed와 버전을 기록합니다.
- 실제 이름, 전화번호, 주민등록번호, 계좌번호를 fixture에 넣지 않습니다.
- 로그·트레이스에는 토큰, API 키, 원문 개인정보를 남기지 않습니다.
- 로컬 비밀은 환경 변수 또는 비추적 설정으로 주입합니다.
- AWS 비밀은 Secrets Manager 또는 동등한 서비스로 주입하고 Terraform state 노출을 검사합니다.
- 원본 AI 프롬프트를 저장할 때도 개인정보 마스킹을 먼저 적용합니다.

## 운영 기준

- 시간은 애플리케이션 내부에서 UTC로 저장하고 화면에서만 변환합니다.
- correlation ID는 HTTP, 이벤트, batch, AI 호출을 관통합니다.
- 주요 지표는 이름, 단위, 분모, 집계 구간을 문서화합니다.
- 부하 테스트는 실행 장비, 데이터 크기, 동시성, duration, warm-up을 기록합니다.
- AWS 배포는 임시 증거 수집용이며, 제거 확인과 비용을 결과에 포함합니다.
