# 제품 비전 — 토스페이먼츠 공개 계약 기반 PG 샌드박스

## 결정

이 저장소가 6개월 동안 진화시킬 제품은 **가맹점이 결제 연동과 장애 복구를 연습할 수 있는 학습용 PG 샌드박스**입니다.

- 외부 계약: 토스페이먼츠 V2 개발자 문서의 선정 API·webhook
- 주요 사용자: 상점 개발자, 상점 운영자, PG 운영자, 샘플 상점의 구매자
- 핵심 업무: 결제 인증 결과 확인, 승인·조회·취소, 가상계좌 입금, webhook, 원장, 대사와 정산
- 데이터와 연동: 합성 주문·결제 데이터와 결정론적 sandbox control API
- 구현 주장: 계약 매트릭스에서 통과한 선정 행만 호환으로 표현

토스페이먼츠의 실제 endpoint를 호출하지 않고 비공개 데이터 모델·원장·인프라를 추정하지 않습니다. 실제 PG 운영, 카드망 처리, 가맹점 계약, 규제 준수 또는 토스 브랜드 제품을 뜻하지 않습니다.

## 한 문장 제품 설명

샘플 상점이 토스페이먼츠 공개 계약과 같은 방식으로 합성 결제를 승인·조회·취소하고, 중복·timeout·webhook·가상계좌·정산 문제를 재현하고 복구할 수 있는 PG 개발 샌드박스입니다.

## 호환 대상으로 선정한 계약

2026-08-28에 확인한 공식 V2 문서를 기준으로 다음을 계약 테스트 대상으로 고정합니다.

1. `POST /v1/payments/confirm`의 `paymentKey`, `orderId`, `amount` 검증
2. `paymentKey`와 `orderId`를 사용한 Payment 조회
3. 전액·부분 취소, 취소 누계와 취소별 `transactionKey`
4. `POST /v1/virtual-accounts` 발급과 입금 전후 상태
5. Payment 상태와 method별 응답 객체
6. Basic 인증, 문서가 지원하는 `Idempotency-Key`, JSON Error 객체와 API 버전
7. `PAYMENT_STATUS_CHANGED`, `CANCEL_STATUS_CHANGED`, `DEPOSIT_CALLBACK`
8. webhook의 10초 ack와 최대 7회 재전송 정책

전체 행과 출처는 [계약 매트릭스](TOSS_PAYMENTS_CONTRACT_MATRIX.md), 공식 문서와 레거시 개선 사례의 용도는 [근거 지도](TOSS_PAYMENTS_EVIDENCE_MAP.md)에서 관리합니다.

## 대표 사용자 흐름

```text
샘플 상점이 합성 주문과 금액을 저장
  → sandbox가 구매자 인증 결과와 paymentKey 생성
  → 상점 서버가 orderId·amount 대조
  → POST /v1/payments/confirm
  → Payment 응답과 불변 journal 연결
  → 상태 변경 webhook 전달·재시도
  → 조회 API로 최종 결과 확인
  → 전액·부분 취소와 Cancel 누계 확인
  → 가상계좌는 발급 뒤 입금 callback으로 DONE 전이
  → 거래 단위 정산과 원장 차이 조사
```

## 모방의 경계

### 모방하는 것

- 선정 API의 경로·헤더·필수 입력·응답 객체·상태·오류 의미
- 공개 webhook event와 전달·재전송 정책
- 상점 개발자가 승인 전 금액·주문번호를 검증하고 결과를 조회하는 흐름
- 공개 정산 개념과 레거시 아티클에서 드러난 실패·개선 질문

### 모방하지 않는 것

- 토스페이먼츠의 비공개 schema, 계정과목, transaction boundary, 네트워크와 조직
- 실제 카드번호·은행 계좌·카드사 전문·가맹점 수수료와 세금
- 빌링·브랜드페이·링크페이·지급대행·해외결제
- 브랜드, 문구, 결제창 UI와 상점관리자 자산
- 기술 아티클의 규모·성능을 이 프로젝트의 성과로 인용하는 것

내부 원장, outbox, read model, 서비스 분리와 AI 통제는 공개 계약을 만족시키기 위한 프로젝트 결정입니다. 토스페이먼츠가 같은 구조를 사용한다고 일반화하지 않습니다.
