# 프로젝트 02 — 결제 승인·조회·취소와 동시성

## 목표

선택한 토스페이먼츠 V2 승인·조회·취소 계약을 샌드박스에서 재현하고, 재시도와 동시 취소에도 결제 금액 불변식이 깨지지 않게 만듭니다.

## 선행 조건

- 프로젝트 01의 결제 집계, 원장, 계약 테스트
- 계약 ID `TP-PAY-001..004`, `TP-WIRE-002..005`, `TP-STATE-001`

## 범위

- `POST /v1/payments/confirm`
- `GET /v1/payments/{paymentKey}`
- `GET /v1/payments/orders/{orderId}`
- `POST /v1/payments/{paymentKey}/cancel`
- 승인·취소 요청의 `Idempotency-Key`
- 부분 취소와 동시 요청 충돌
- 응답 유실 후 조회 또는 같은 키 재시도
- 샘플 상점의 승인·부분 취소 화면

## 불변식

1. 같은 MID·멱등키·동일 요청은 같은 의미의 응답을 돌려줍니다.
2. 같은 멱등키에 다른 요청 본문은 충돌로 거절합니다.
3. 승인 완료된 결제만 취소할 수 있습니다.
4. 누적 취소액은 승인 금액을 넘지 않습니다.
5. 동시 부분 취소 중 성공한 합계와 원장 역분개 합계가 일치합니다.
6. 타임아웃은 성공·실패를 추측하지 않고 조회 또는 동일 키 재시도로 확정합니다.
7. 상태, Cancel 배열, 원장 기록은 한 트랜잭션 경계에서 일관됩니다.

## 동시성 실험

최소 두 전략을 실제로 구현·계측한 뒤 하나를 선택합니다.

- 비관적 잠금
- 낙관적 잠금과 제한 재시도
- 조건부 원자 업데이트

동일 워크로드와 데이터셋으로 성공률, 충돌률, p95 지연, DB 대기 시간을 비교합니다. 수치는 원시 결과와 명령이 있을 때만 성과로 표기합니다.

## 구현 순서

1. 승인·취소 상태 전이와 오류 매핑을 표로 고정합니다.
2. 멱등 요청 저장소와 요청 해시 규칙을 구현합니다.
3. 부분 취소와 역분개를 구현합니다.
4. 세 동시성 후보 중 최소 두 개를 실험합니다.
5. 응답 유실·재시도·조회 복구 시나리오를 테스트합니다.
6. 샘플 상점과 계약 회귀 테스트를 연결합니다.

## 실패 주입

- DB 커밋 직전 예외
- 커밋 후 응답 유실
- 같은 결제에 대한 N개 동시 부분 취소
- 같은 멱등키에 다른 amount
- 이미 전액 취소된 결제의 재취소

- 동시성 전략 비교 보고서와 원시 측정값
- 금액 보존 속성 테스트
