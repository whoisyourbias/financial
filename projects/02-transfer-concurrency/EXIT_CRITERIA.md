# 프로젝트 02 종료 기준

## 기능·정합성 게이트

- [ ] 성공 이체 전후 관련 계정 총액이 보존됩니다.
- [ ] 동시 출금으로 정책 밖 음수 잔액이 생기지 않습니다.
- [ ] 이체는 ledger port로만 posting을 생성합니다.
- [ ] 같은 멱등 키·같은 요청은 같은 결과를 반환합니다.
- [ ] 같은 멱등 키·다른 요청은 충돌하며 금전 변경이 없습니다.
- [ ] timeout 뒤 재조회·재시도로 확정 상태를 찾을 수 있습니다.
- [ ] deadlock·lock timeout의 처리와 상한이 정의돼 있습니다.

## 비교·증거 게이트

- [ ] 최소 두 동시성 전략을 같은 workload에서 실제 실행했습니다.
- [ ] low-contention과 hot-account 결과를 섞지 않았습니다.
- [ ] 환경, 계좌 수, 초기 잔액, request mix, duration이 기록돼 있습니다.
- [ ] latency의 시작·종료 지점과 p50/p95/p99 분모가 기록돼 있습니다.
- [ ] 시작·종료 총액과 고유 transfer·journal 수 원본이 있습니다.
- [ ] conflict·retry·lock wait 원본이 있습니다.
- [ ] 실험하지 않은 전략은 `미실험`으로 표시했습니다.

## Portfolio Review 평가표

| 영역            | PASS 근거                                      |
| --------------- | ---------------------------------------------- |
| 기술적 의사결정 | 경합 메커니즘과 실제 잠금 전략 비교, 선택 비용 |
| 문제 해결       | 중복·timeout·deadlock을 포함한 자금 보존 과정  |
| 성과·임팩트     | 같은 workload의 정합성·지연·충돌 원본 결과     |

- [ ] 세 영역 모두 `적합` 이상입니다.
- [ ] 선택한 전략의 장점뿐 아니라 불리한 workload를 공개했습니다.
- [ ] 대표 수치에 🔴 정합성 결함이 없습니다.

## Red Team 공격 목록

- [ ] 개인 장비 workload를 실제 금융 트래픽으로 표현하지 않았습니다.
- [ ] 평균 latency를 p95·p99처럼 쓰지 않았습니다.
- [ ] 오류·거절 요청을 제외했다면 분모와 제외 수를 기록했습니다.
- [ ] 멱등성을 exactly-once로 표현하지 않았습니다.
- [ ] retry가 성공률을 높였다는 인과를 다른 변경과 섞지 않았습니다.
- [ ] 전략 비교에서 데이터·duration·request mix가 동일합니다.

## 면접 방어

- [ ] lock ordering과 deadlock 예를 설명할 수 있습니다.
- [ ] timeout과 비즈니스 실패를 구분할 수 있습니다.
- [ ] 선택한 전략이 불리해지는 경합 조건을 설명할 수 있습니다.
- [ ] idempotency payload fingerprint와 transaction 경계를 설명할 수 있습니다.
- [ ] projection 불일치 복구 순서를 설명할 수 있습니다.

## 판정 기록

| 항목             | 프로젝트 종료 시 기록        |
| ---------------- | ---------------------------- |
| Portfolio Review | PASS 또는 REJECT             |
| Red Team         | 🔴 / 🟠 / 🟡 / `[밋밋]` 건수 |
| 선택 전략        | 실제 채택안과 비교 근거      |
| Evidence         | commit SHA와 manifest 경로   |
| 최종 상태        | RELEASED 또는 HOLD           |

자금 보존 실패, 중복 transfer 생성, 비교 조건 불일치 또는 🔴가 남으면 태그를 생성하지 않습니다.
