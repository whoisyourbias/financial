# 프로젝트 01 종료 기준

## 기능·정합성 게이트

- [ ] 균형 journal entry가 하나의 transaction으로 저장됩니다.
- [ ] debit·credit 합계가 다르면 저장되지 않습니다.
- [ ] 서로 다른 통화를 같은 entry에서 상계하지 않습니다.
- [ ] 확정된 journal·posting의 update/delete가 차단됩니다.
- [ ] 동일 외부 참조와 다른 본문의 재사용이 충돌로 처리됩니다.
- [ ] 계정 시점 잔액을 posting으로 재계산할 수 있습니다.
- [ ] 저장 중 실패 시 부분 journal·posting이 남지 않습니다.

## 테스트·증거 게이트

- [ ] 단위·통합·생성형 테스트 명령과 결과가 manifest에 있습니다.
- [ ] 생성형 테스트 seed와 case 수가 기록돼 있습니다.
- [ ] rollback 전후 데이터가 원본 query로 확인됩니다.
- [ ] Flyway migration이 빈 PostgreSQL에서 재현됩니다.
- [ ] ERD와 실제 schema의 table·column이 일치합니다.
- [ ] 모든 결과가 commit SHA와 연결됩니다.
- [ ] 실제로 구현하지 않은 회계 기능을 결과에서 제외했습니다.

## Portfolio Review 평가표

| 영역            | PASS 근거                                                             |
| --------------- | --------------------------------------------------------------------- |
| 기술적 의사결정 | 잔액 직접 저장·합계 조회·projection 후보의 실제 검토 범위와 선택 비용 |
| 문제 해결       | 여섯 금융 불변식이 테스트·DB 방어와 연결됨                            |
| 성과·임팩트     | 불변식 위반·rollback·중복 참조 결과가 원본과 정합                     |

- [ ] 세 영역 모두 `적합` 이상입니다.
- [ ] 기술 스택·ERD·코드의 서사가 일치합니다.
- [ ] 대표 결과에 🔴 정합성 결함이 없습니다.

## Red Team 공격 목록

- [ ] `복식부기`를 사용했지만 지원 계정 유형과 비범위를 명확히 적었습니다.
- [ ] 불변식 성공 case 수를 실제 금융 규모로 표현하지 않았습니다.
- [ ] journal append-only 구현을 event sourcing이라고 부르지 않았습니다.
- [ ] 애플리케이션 검증과 DB 방어를 혼동하지 않았습니다.
- [ ] 평균·합계·개별 거래 정합성을 바꿔 쓰지 않았습니다.
- [ ] 실제 검토하지 않은 잔액 대안을 비교했다고 쓰지 않았습니다.

## 면접 방어

- [ ] 잔액 source of truth와 projection 복구 순서를 설명할 수 있습니다.
- [ ] 정정 posting 예시를 숫자로 설명할 수 있습니다.
- [ ] DB transaction 경계와 부분 실패 방어를 설명할 수 있습니다.
- [ ] 현재 모델이 실제 은행 원장과 다른 점을 세 가지 이상 말할 수 있습니다.
